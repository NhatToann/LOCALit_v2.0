fix(map): switch tile provider to CARTO Positron, fix resize + zoom reset

ROOT CAUSE
tile.openstreetmap.org was returning 400 + ERR_CONNECTION_RESET
for every tile request from production traffic. Cloud IPs (incl.
Vercel) are rate-limited / blocked by OSM tile policy. Result: 0
of 18 tile <img> elements ever reached the .leaflet-tile-loaded
state, so the tile pane rendered blank gray while the marker pane
was perfectly on top of it. From the user's POV it looked like
"markers float over an empty gray void" — exactly the "multiple
map layers stacked" feeling.

FIXES

1. Tile provider swap (the big one)
   https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png
   -> https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}{r}.png
   CARTO Positron is free, CORS-friendly, serves via a global CDN
   with no auth and no rate limit at our scale. The light_all style
   matches LOCALit's --paper #FAFAF7 background, so the map blends
   with the rest of the page. Attribution is updated to credit both
   OSM (data) and CARTO (hosting). subdomains a/b/c/d for
   parallelism.

2. FlyToUser -> RecenterOnUserMove
   Old: map.setView([lat,lng], 13) every time the component
   re-rendered. This forced zoom 13 on every state change, which is
   why user-initiated zoom appeared to do nothing — Leaflet was
   re-pinning to zoom 13 the moment any other piece of state
   (buddies hydrating, tourists streaming, marker re-render)
   caused a re-render.
   New: map.flyTo([lat,lng], map.getZoom()) — uses the user's
   CURRENT zoom, and only when the user moved > 50m AND it's been
   > 5s since the last recentre. Users can grab the map, pan / zoom
   away, and it stays where they put it.

3. New MapResizer
   react-leaflet 5 calls invalidateSize() once on mount, but if
   the parent reflows (buddy list hydrating, layout shift, browser
   zoom) the tile pane keeps the old dimensions and tiles stop
   drawing. We now:
   - call invalidateSize on next animation frame
   - call invalidateSize 200ms after mount (catches late reflows)
   - observe the container with ResizeObserver and re-fire on any
     size change, debounced 100ms
   - re-fire when `loading` flips false (biggest layout shift on
     /dashboard and /browse is the buddy list hydrating)

4. Cleanup of redundant state
   - Removed mapRef (was being set in 2 places, never read after
     the previous memory-leak fix).
   - Simplified MapDisposer: no more map.off() on React unmount
     (react-leaflet 5 owns the instance lifecycle; calling off()
     ourselves caused "Map container is being reused by another
     instance" warnings in earlier sessions). Still calls off() on
     beforeunload so a slow tab close doesn't keep sockets open.

WHY POSITRON (not Voyager / Dark Matter)
- Matches --paper #FAFAF7 (warm white). Da Nang travel context,
  tourist-friendly.
- No street labels = less visual noise, lets the buddy markers
  (B in primary orange) and self-marker (Y in ink black) be the
  dominant UI elements on the map.
- No 3D buildings / hill shading = fast tile load on the same
  zoom levels OSM was failing to serve.

VERIFIED
- diag-dashboard-map-state.mjs: tiles load, tilePane tracks
  container size, zoom-in click changes tile count.
- diag-map-network.mjs: 0 failures, all tile requests return 200.
- Build: 26 routes, 0 TS errors.
